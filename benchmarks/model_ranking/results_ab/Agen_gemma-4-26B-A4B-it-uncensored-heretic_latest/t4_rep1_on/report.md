## Timeline
The supply chain attack campaign known as "Shai-Hulud" first emerged in September 2025, when researchers identified a self-replicating worm compromising hundreds of npm packages [2]. This initial wave was followed by an even more widespread and aggressive escalation dubbed "Shai-Hulud 2.0," which was reported in early November 2025 [1]. By the time this second phase was documented, it had expanded to affect over 25,000 malicious repositories across approximately 350 unique users [1].

## How it spreads
The initial "Shai-Hulud" worm utilized a sophisticated multi-stage chain involving a Webpack-bundled script (`bundle.js`) that leveraged Node.js modules for reconnaissance and credential harvesting [2]. The core of its propagation was the `NpmModule.updatePackage` function, which queried the NPM registry API to identify up to 20 packages owned by a compromised maintainer [2]. Once identified, the malware would force-publish malicious patches to these downstream packages, creating a cascading infection across the npm ecosystem [2]. This mechanism specifically targeted developers on Linux and macOS who had access to NPM, GitHub, or cloud credentials [2].

The "Shai-Hulud 2.0" campaign introduced significant changes to its execution method to increase its effectiveness [1]. Instead of relying on post-install scripts, this version targeted the `preinstall` phase of software dependencies [1]. This shift allowed the malware to bypass many static scanning tools that are designed to inspect code during later stages of the build process [1]. The 2.0 variant also introduced new payload files, specifically `setup_bun.js` and `bun_environment.js`, as part of its execution [1]. Additionally, this version featured a more aggressive fallback mechanism that could potentially attempt to destroy a user's home directory on the infected machine [1]. To facilitate data exfiltration, stolen credentials and secrets were sent to public GitHub repositories characterized by the description “Sha1-Hulud: The Second Coming” [1].

## Remediation steps
The primary remediation for the initial wave of attacks involved the removal of compromised package versions from the npm registry [2]. For organizations managing large dependency trees, auditing the integrity of all `preinstall` scripts is a vital step in preventing future infections from similar campaigns [1]. Because "Shai-Hulud 2.0" was specifically designed to bypass static analysis by executing during the early installation phase, traditional code-level inspections may be insufficient for detection [1]. Organizations should also monitor CI/CD pipelines for unauthorized credential exfiltration or unexpected file system changes, as this campaign demonstrated the ability to escalate from simple espionage into disruptive denial-of-service events [1]. Ensuring that build environments are strictly scoped and that package locks are verified can help mitigate the impact of such widespread supply chain compromises [2].
