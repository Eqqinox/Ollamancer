## Timeline
The "Shai-Hulud" supply chain campaign emerged in late 2025, with initial investigations into a self-replicating worm occurring around September 2025 [4]. By November 25, 2025, the attack had escalated into the "Shai-Hulud 2.0" phase, which researchers at Unit 42 identified as significantly wider in scope, affecting over 25,000 malicious repositories across hundreds of users [1]. The campaign continued into 2026; specifically, a variant known as "Mini Shai Hulud" was discovered on May 20, 2026, targeting the @antv npm package ecosystem and its widespread dependencies like `echarts-for-react` [2].

## How it spreads
The attack leverages the Node.js package manager (npm) ecosystem through automated propagation [4]. The malware typically executes during the `preinstall` or `postinstall` lifecycle hooks of a package installation [1][2]. This allows for execution on virtually every build server processing an infected package without requiring human interaction [1]. A sophisticated self-propagation engine queries the NPM registry API to find packages owned by compromised maintainers and then force-publishes malicious patches to those packages, creating a cascading effect throughout the dependency tree [4]. The payload is designed to be stealthy, often using obfuscated JavaScript files (such as `setup_bun.js` or `bundle.js`) that can even install the Bun runtime if it is not already present on the system to ensure execution [1][2][4]. Once active, the worm targets high-value cloud credentials and secrets from environments like GitHub Actions, AWS, HashiCorp Vault, and Kubernetes [2]. Stolen data is exfiltrated to public GitHub repositories characterized by the description "Sha1-Hulud: The Second Coming" [1].

## Remediation steps
Effective remediation requires a strict order of operations to prevent the malware from compromising newly issued credentials [3]. First, practitioners must contain the breach by privatizing any identified malicious GitHub repositories and disabling compromised workflows or self-hosted runners named "SHA1HULUD" [3]. Next, all infected packages must be removed from `node_modules`, and the npm cache must be cleared to ensure no malicious artifacts remain in the local environment [3]. Only after these containment steps are complete should organizations proceed with rotating all compromised credentials, including GitHub tokens, npm credentials, and cloud-based keys [3]. It is vital that rotation does not happen before package removal, as the malware's ability to scrape process memory can lead it to steal the new secrets immediately [2][3].
