# Shai-Hulud npm Supply-Chain Worm Campaign

## Timeline

On September 15, 2025, a self-replicating worm publicly known as "Shai-Hulud" compromised over 500 packages in the npm registry [Source: https://www.cisa.gov/news-events/alerts/2025/09/23/widespread-supply-chain-compromise-impacting-npm-ecosystem]. The attack was traced downstream to an earlier breach of the s1ngularity/Nx repository that yielded initial GitHub tokens used to publish malicious versions across dozens of popular packages [Source: https://www.wiz.io/blog/shai-hulud-npm-supply-chain-attack]. By September 23, CISA issued a formal alert warning organizations about the widespread compromise and urged immediate credential rotation [Source: https://www.cisa.gov/news-events/alerts/2025/09/23/widespread-supply-chain-compromise-impacting-npm-ecosystem]. A second wave — Shai-Hulud 2.0 — was detected on December 9, 2025, featuring faster propagation through preinstall scripts that executed before tests or security checks could run [Source: https://www.microsoft.com/en-us/security/blog/2025/12/09/shai-hulud-2-0-guidance-for-detecting-investigating-and-defending-against-the-supply-chain-attack/]. In May 2026, a resurgence called "Mini Shai-Hulud" compromised an additional 170+ npm packages and two PyPI packages across more than 400 malicious versions [Source: https://www.microsoft.com/en-us/security/blog/2025/12/09/shai-hulud-2-0-guidance-for-detecting-investigating-and-defending-against-the-supply-chain-attack/].

## How it spreads

The worm embeds a post-install script in package.json that uses the TruffleHog secret-scanning tool to harvest credentials from the victim environment, including GitHub Personal Access Tokens (PATs), AWS keys, GCP service accounts, and Azure secrets [Source: https://www.cisa.gov/news-events/alerts/2025/09/23/widespread-supply-chain-compromise-impacting-npm-ecosystem][Source: https://www.wiz.io/blog/shai-hulud-npm-supply-chain-attack]. Stolen tokens are exfiltrated to attacker-controlled public repositories named "Shai-Hulud" via the `GitHub/user/repos` API [Source: https://www.cisa.gov/news-events/alerts/2025/09/23/widespread-supply-chain-compromise-impacting-npm-ecosystem]. The payload then validates each credential; when a valid npm token is found in the environment, it automatically authenticates as that developer and publishes malicious versions of other accessible packages — making Shai-Hulud one of the first successful self-propagating attacks in the JavaScript ecosystem [Source: https://www.wiz.io/blog/shai-hulud-npm-supply-chain-attack][Source: https://www.microsoft.com/en-us/security/blog/2025/12/09/shai-hulud-2-0-guidance-for-detecting-investigating-and-defending-against-the-supply-chain-attack/]. In later variants (Shai-Hulud 2.0), a preinstall script called `set_bun.js` runs before any security checks, downloads and installs a GitHub Actions Runner archive containing TruffleHog and other credential-stealing tools [Source: https://www.microsoft.com/en-us/security/blog/2025/12/09/shai-hulud-2-0-guidance-for-detecting-investigating-and-defending-against-the-supply-chain-attack/].

## Remediation steps

CISA recommends pinning npm package dependency versions to known-safe releases produced prior to September 16, 2025, and conducting a full dependency review of every project using the npm ecosystem [Source: https://www.cisa.gov/news-events/alerts/2025/09/23/widespread-supply-chain-compromise-impacting-npm-ecosystem]. Organizations should immediately rotate all developer credentials — GitHub tokens, npm tokens, SSH keys, API keys for AWS/GCP/Azure, and any environment-variable secrets that may have been leaked in public repositories [Source: https://www.wiz.io/blog/shai-hulud-npm-supply-chain-attack][Source: https://www.cisa.gov/news-events/alerts/2025/09/23/widespread-supply-chain-compromise-impacting-npm-ecosystem]. Phishing-resistant multifactor authentication must be enforced on all developer accounts, especially those with access to critical platforms like GitHub and the npm registry [Source: https://www.cisa.gov/news-events/alerts/2025/09/23/widespread-supply-chain-compromise-impacting-npm-ecosystem]. Network controls should block outbound connections to `webhook.site` domains (used by the attacker for exfiltration) and monitor firewall logs for suspicious domain communication [Source: https://www.cisa.gov/news-events/alerts/2025/09/23/widespread-supply-chain-compromise-impacting-npm-ecosystem][Source: https://www.wiz.io/blog/shai-hulud-npm-supply-chain-attack]. Finally, harden GitHub security by removing unnecessary apps and OAuth applications, auditing repository webhooks and secrets, enabling branch protection rules, activating GitHub Secret Scanning alerts, and relying on Dependabot or equivalent tools for automated dependency updates [Source: https://www.cisa.gov/news-events/alerts/2025/09/23/widespread-supply-chain-compromise-impacting-npm-ecosystem].
