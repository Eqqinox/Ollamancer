## Timeline

The Shai-Hulud campaign began in September 2025 when a self-replicating npm worm was identified, compromising over 500 packages within the JavaScript ecosystem [Source: https://www.cisa.gov/news-events/alerts/2025/09/23/widespread-supply-chain-compromise-impacting-npm-ecosystem]. CISA issued an official alert on September 23, 2025 confirming the widespread supply chain compromise and providing initial remediation guidance for affected organizations [Source: https://www.cisa.gov/news-events/alerts/2025/09/23/widespread-supply-chain-compromise-impacting-npm-ecosystem].

A significantly more aggressive variant emerged in November. Shai-Hulud 2.0 was first reported by security researchers around November 24–25, 2025, marking a major escalation in both scope and sophistication [Source: https://unit42.paloaltonetworks.com/npm-supply-chain-attack/][Source: https://securitylabs.datadoghq.com/articles/shai-hulud-2.0-npm-worm/]. This second campaign targeted tens of thousands of GitHub repositories across approximately 350 unique users, with the worm successfully backdooring 796 unique npm packages totaling over 20 million weekly downloads [Source: https://securitylabs.datadoghq.com/articles/shai-hulud-2.0-npm-worm/]. The rapid propagation continued until approximately November 24 at 6 p.m. UTC, suggesting that defensive measures may have been implemented by npm to halt further compromise [Source: https://securitylabs.datadoghq.com/articles/shai-hulud-2.0-npm-worm/].

## How it spreads

Shai-Hulud operates as a self-replicating worm capable of spreading without direct command-and-control communication [Source: https://unit42.paloaltonetworks.com/npm-supply-chain-attack/][Source: https://securitylabs.datadoghq.com/articles/shai-hulud-2.0-npm-worm/]. The attack begins when the malware infects legitimate npm packages by injecting two malicious files: setup_bun.js and bun_environment.js [Source: https://securitylabs.datadoghq.com/articles/shai-hulud-2.0-npm-worm/]. These are triggered through a newly added preinstall script in the package metadata [Source: https://securitylabs.datadoghq.com/articles/shai-hulud-2.0-npm-worm/].

The infection chain proceeds as follows: first, the worm installs the Bun JavaScript runtime to potentially evade standard Node.js monitoring systems and execute an obfuscated payload [Source: https://securitylabs.datadoghq.com/articles/shai-hulud-2.0-npm-worm/]. It then scans both local filesystems and cloud environments for sensitive credentials targeting AWS, Google Cloud Platform, and Microsoft Azure accounts [Source: https://www.cisa.gov/news-events/alerts/2025/09/23/widespread-supply-chain-compromise-impacting-npm-ecosystem].

Once harvested, stolen developer tokens and API keys are exfiltrated through a public GitHub repository specifically named "Sha1-Hulud: The Second Coming" [Source: https://unit42.paloaltonetworks.com/npm-supply-chain-attack/][Source: https://securitylabs.datadoghq.com/articles/shai-hulud-2.0-npm-worm/]. The worm's self-replication mechanism reads its own code content to propagate into additional npm packages without external coordination [Source: https://securitylabs.datadoghq.com/articles/shai-hulud-2.0-npm-worm/]. In the November campaign, execution during the pre-install phase eliminated the need for human interaction, guaranteeing activation on nearly every build server processing infected dependencies while bypassing many static scanning tools that inspect code at later build stages [Source: https://unit42.paloaltonetworks.com/npm-supply-chain-attack/].

## Remediation steps

Organizations should immediately conduct a comprehensive dependency review of all software leveraging npm packages to identify affected versions in their supply chains and nested dependency trees [Source: https://www.cisa.gov/news-events/alerts/2025/09/23/widespread-supply-chain-compromise-impacting-npm-ecosystem][Source: https://securitylabs.datadoghq.com/articles/shai-hulud-2.0-npm-worm/]. Pinning package dependency versions to known safe releases produced prior to September 16, 2025 is critical for preventing exposure to compromised code [Source: https://www.cisa.gov/news-events/alerts/2025/09/23/widespread-supply-chain-compromise-impacting-npm-ecosystem].

All developer credentials must be rotated without delay following any suspected compromise. Mandating phishing-resistant multifactor authentication on all developer accounts, particularly those with GitHub and npm access, significantly reduces the risk of future credential theft enabling worm propagation [Source: https://www.cisa.gov/news-events/alerts/2025/09/23/widespread-supply-chain-compromise-impacting-npm-ecosystem][Source: https://securitylabs.datadoghq.com/articles/shai-hulud-2.0-npm-worm/]. Network monitoring should include blocking outbound connections to webhook.site domains and watching firewall logs for suspicious domain communications [Source: https://www.cisa.gov/news-events/alerts/2025/09/23/widespread-supply-chain-compromise-impacting-npm-ecosystem].

For Shai-Hulud 2.0 specifically, organizations must search cached artifact repositories for compromised dependency versions and verify that build pipelines are not executing malicious preinstall scripts from infected packages [Source: https://unit42.paloaltonetworks.com/npm-supply-chain-attack/][Source: https://securitylabs.datadoghq.com/articles/shai-hulud-2.0-npm-worm/]. Monitoring CI/CD pipeline behavior is essential since the worm can cripple enterprise development workflows through denial-of-service effects on internal systems [Source: https://unit42.paloaltonetworks.com/npm-supply-chain-attack/].
