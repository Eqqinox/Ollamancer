# Shai-Hulud npm Supply-Chain Worm Report

## Timeline

The first wave began on September 8, 2025 when a phishing campaign spoofing npm MFA login pages compromised developer credentials [1] [Source: https://www.stepsecurity.io/blog/ctrl-tinycolor-and-40-npm-packages-compromised]. Between September 9 and 16, the self-replicating worm spread through more than 40 packages including @ctrl/tinycolor (2 million weekly downloads), with StepSecurity documenting over 500 affected packages by September 15 [1] [Source: https://www.stepsecurity.io/blog/ctrl-tinycolor-and-40-npm-packages-compromised] and CISA releasing an alert on September 23 describing widespread compromise of hundreds of npm packages [2] [Source: https://www.cisa.gov/news-events/alerts/2025/09/23/widespread-supply-chain-compromise-impacting-npm-ecosystem].

The second wave, dubbed "Shai-Hulud 2.0," emerged in November 2025 when the campaign shifted its execution point from post-install to preinstall scripts [3] [Source: https://unit42.paloaltonetworks.com/npm-supply-chain-attack/], dramatically widening impact across CI/CD pipelines and developer machines. By December 9, Microsoft reported that hundreds of packages had been compromised, including Zapier, PostHog, and Postman; malicious code executed during the preinstall phase via a `set_bun.js` script [4] [Source: https://www.microsoft.com/en-us/security/blog/2025/12/09/shai-hulud-2-0-guidance-for-detecting-investigating-and-defending-against-the-supply-chain-attack/] that installed or used Bun runtime to run a credential stealer (`bun_environment.js`).

A resurgence called "Mini Shai-Hulud" occurred on May 11, 2026 when Microsoft Security Research identified over 170 npm packages and 2 PyPI packages compromised across 404 malicious versions—the first supply-chain attack to simultaneously span both registries in a single coordinated operation [4] [Source: https://www.microsoft.com/en-us/security/blog/2025/12/09/shai-hulud-2-0-guidance-for-detecting-investigating-and-defending-against-the-supply-chain-attack/].

## How it spreads

The worm begins by compromising maintainer accounts through credential theft. Harvested GitHub personal access tokens allow the attacker to authenticate as the developer and inject code into other packages owned by that account [1] [Source: https://www.stepsecurity.io/blog/ctrl-tinycolor-and-40-npm-packages-compromised]. The malicious payload is embedded via Webpack-bundled JavaScript (~3.6 MB of minified `bundle.js`) executed during npm install, which scans for sensitive credentials including AWS keys (`AKIA` pattern), GCP service accounts, Azure tokens, and environment variables such as `GITHUB_TOKEN` and `AWS_ACCESS_KEY_ID` [1] [Source: https://www.stepsecurity.io/blog/ctrl-tinycolor-and-40-npm-packages-compromised].

Self-propagation occurs through the NPM registry API: the malware queries up to 20 packages owned by the compromised maintainer using `NpmModule.updatePackage`, then force-publishes patched versions containing the malicious bundle, creating cascading compromise across the ecosystem [1] [Source: https://www.stepsecurity.io/blog/ctrl-tinycolor-and-40-npm-packages-compromised]. In Shai-Hulud 2.0, a preinstall script (`set_bun.js`) downloads and installs a GitHub Actions Runner archive; it extracts TruffleHog to query stored credentials on disk [4] [Source: https://www.microsoft.com/en-us/security/blog/2025/12/09/shai-hulud-2-0-guidance-for-detecting-investigating-and-defending-against-the-supply-chain-attack/] and cloud metadata endpoints for secrets in AWS Secrets Manager, GCP Secret Manager, and Azure. Harvested credentials are uploaded via the GitHub `/user/repos` API to a public repository named "Shai-Hulud" under the victim's account [1] [Source: https://www.stepsecurity.io/blog/ctrl-tinycolor-and-40-npm-packages-compromised].

The worm also establishes persistence by injecting a GitHub Actions workflow file (`.github/workflows/shai-hulud-workflow.yml`) that triggers on push events and exfiltrates `${{ toJSON(secrets) }}` via `toJSON()` to a command-and-control endpoint; it can force-merge branches using `/git/refs` [1] [Source: https://www.stepsecurity.io/blog/ctrl-tinycolor-and-40-npm-packages-compromised]. In Shai-Hulud 2.0, if the worm fails to exfiltrate credentials, it attempts destructive sabotage by shredding every writable file in the victim's home directory using TruffleHog and `Runner.Listener`, producing a denial-of-service effect [3] [Source: https://unit42.paloaltonetworks.com/npm-supply-chain-attack/] [4] [Source: https://www.microsoft.com/en-us/security/blog/2025/12/09/shai-hulud-2-0-guidance-for-detecting-investigating-and-defending-against-the-supply-chain-attack/].

## Remediation steps

- Pin npm package dependency versions to known-safe releases produced before September 16, 2025 (or May 11 for Mini Shai-Hulud) [2] [Source: https://www.cisa.gov/news-events/alerts/2025/09/23/widespread-supply-chain-compromise-impacting-npm-ecosystem].
- Review all `package-lock.json` and `yarn.lock` files for affected packages across direct and transitive dependencies [2] [Source: https://www.cisa.gov/news-events/alerts/2025/09/23/widespread-supply-chain-compromise-impacting-npm-ecosystem].
- Rotate all developer credentials including GitHub PATs, AWS access keys, GCP service accounts, and Azure tokens [1] [Source: https://www.stepsecurity.io/blog/ctrl-tinycolor-and-40-npm-packages-compromised] [2] [Source: https://www.cisa.gov/news-events/alerts/2025/09/23/widespread-supply-chain-compromise-impacting-npm-ecosystem].
- Mandate phishing-resistant MFA on all developer accounts, especially for critical platforms like GitHub and npm [2] [Source: https://www.cisa.gov/news-events/alerts/2025/09/23/widespread-supply-chain-compromise-impacting-npm-ecosystem].
- Block outbound connections to webhook domains used by the worm (e.g., `webhook.site`) and monitor firewall logs for suspicious traffic [2] [Source: https://www.cisa.gov/news-events/alerts/2025/09/23/widespread-supply-chain-compromise-impacting-npm-ecosystem].
- Harden GitHub security: remove unnecessary GitHub Apps and OAuth applications; audit repository webhooks and secrets; enable branch protection rules, Secret Scanning alerts, and Dependabot updates [2] [Source: https://www.cisa.gov/news-events/alerts/2025/09/23/widespread-supply-chain-compromise-impacting-npm-ecosystem].
- Detect preinstall-phase infections by inspecting package `preinstall` scripts in `package.json`, particularly those referencing `set_bun.js` or `bun_environment.js`; look for Bun runtime installations triggered during CI/CD builds [3] [Source: https://unit42.paloaltonetworks.com/npm-supply-chain-attack/] [4] [Source: https://www.microsoft.com/en-us/security/blog/2025/12/09/shai-hulud-2-0-guidance-for-detecting-investigating-and-defending-against-the-supply-chain-attack/].
- Search filesystems and cloud metadata endpoints using TruffleHog to identify leaked credentials; check GitHub repositories named "Shai-Hulud" under compromised accounts [1] [Source: https://www.stepsecurity.io/blog/ctrl-tinycolor-and-40-npm-packages-compromised] [4] [Source: https://www.microsoft.com/en-us/security/blog/2025/12/09/shai-hulud-2-0-guidance-for-detecting-investigating-and-defending-against-the-supply-chain-attack/].
