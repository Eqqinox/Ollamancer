# Shai-Hulud: npm Supply-Chain Worm Campaign (2025–2026)

## Timeline

On September 14, 2025, researchers at ReversingLabs discovered a self-replicating worm in the npm registry that was infecting legitimate packages by injecting malicious post-install scripts (StepSecurity: https://www.stepsecurity.io/blog/ctrl-tinycolor-and-40-npm-packages-compromised). By September 17, over 500 npm packages had been compromised across dozens of projects including widely used libraries such as @ctrl/tinycolor and ngx-bootstrap (CISA alert: https://www.cisa.gov/news-events/alerts/2025/09/23/widespread-supply-chain-compromise-impacting-npm-ecosystem; Zscaler blog: https://www.zscaler.com/blogs/security-research/mitigating-risks-shai-hulud-npm-worm). The campaign earned the name "Shai-Hulud" from a GitHub repository created by the attacker to store exfiltrated credentials. On November 24, 2025, researchers identified a second wave dubbed Shai-Hulud 2.0 that shifted execution to the preinstall phase and introduced home-directory destruction as a fallback (Datadog Labs: https://securitylabs.datadoghq.com/articles/shai-hulud-2.0-npm-worm; Palo Alto Networks Unit42: https://unit42.paloaltonetworks.com/npm-supply-chain-attack/). This version affected over 796 unique npm packages with more than 20 million weekly downloads combined (Datadog Labs: https://securitylabs.datadoghq.com/articles/shai-hulud-2.0-npm-worm). On December 9, Microsoft published detailed analysis of Shai-Hulud 2.0's mechanics including CI cache poisoning and OIDC abuse (Microsoft Blog: https://www.microsoft.com/en-us/security/blog/2025/12/09/shai-hulud-2-0-guidance-for-detecting-investigating-and-defending-against-the-supply-chain-attack/). On May 11, 2026, a resurgence dubbed "Mini Shai-Hulud" compromised over 170 npm packages plus two PyPI packages across 404 malicious versions—the first coordinated cross-ecosystem attack spanning both registries simultaneously (Akamai Blog: https://www.akamai.com/blog/security-research/mini-shai-hulud-worm-returns-goes-public; Microsoft Blog: https://www.microsoft.com/en-us/security/blog/2025/12/09/shai-hulud-2-0-guidance-for-detecting-investigating-and-defending-against-the-supply-chain-attack/).

## How it spreads

The worm infects legitimate npm packages by injecting two files—`setup_bun.js` and `bun_environment.js`—into the package's preinstall script (Datadog Labs: https://securitylabs.datadoghq.com/articles/shai-hulud-2.0-npm-worm). When a victim runs `npm install`, the payload first installs or detects the Bun JavaScript runtime, then executes an obfuscated credential stealer (Datadog Labs: https://securitylabs.datadoghq.com/articles/shai-hulud-2.0-npm-worm; Palo Alto Networks Unit42: https://unit42.paloaltonetworks.com/npm-supply-chain-attack/). The malware scans for sensitive files on disk (.npmrc, `.config/gcloud/application_default_credentials.json`) and queries cloud metadata services (AWS, GCP, Azure) to harvest temporary workload credentials. It also downloads TruffleHog to actively hunt for secrets stored in the environment (Zscaler: https://www.zscaler.com/blogs/security-research/mitigating-risks-shai-hulud-npm-worm; Microsoft Blog: https://www.microsoft.com/en-us/security/blog/2025/12/09/shai-hulud-2-0-guidance-for-detecting-investigating-and-defending-against-the-supply-chain-attack/). Harvested tokens are exfiltrated by creating a public GitHub repository with description "Sha1-Hulud: The Second Coming" and committing stolen data as files (Datadog Labs: https://securitylabs.datadoghq.com/articles/shai-hulund-2.0-npm-worm). To propagate, the worm reads its own content from disk using the victim's npm token to authenticate as that developer, discovers other packages maintained by the same account, injects malicious code into each one, publishes new compromised versions, and repeats—self-replicating without a command-and-control server. If exfiltration fails entirely, the malware falls back to securely shredding every writable file in the user's home directory (Datadog Labs: https://securitylabs.datadoghq.com/articles/shai-hulund-2.0-npm-worm; Palo Alto Networks Unit42: https://unit42.paloaltonetworks.com/npm-supply-chain-attack/).

## Remediation steps

Organizations should pin npm package dependencies to known-safe releases produced before September 16, 2025 or re-install clean versions after detection [8]. Rotate all developer credentials including npm tokens and GitHub personal access tokens (PATs) immediately. Enable phishing-resistant multi-factor authentication on all developer accounts for npm and GitHub [8]. Search lock files (`package-lock.json`, `yarn.lock`) for affected packages, clear caches, and reinstall from clean registries. Block outbound connections to `webhook.site` domains in firewalls or proxy configurations [8]. Use private registry proxies or software composition analysis tools (e.g., Socket, SCA scanners) to filter third-party packages before installation [4]. Harden GitHub repositories by removing unnecessary OAuth applications and GitHub Apps, enabling branch protection rules, secret scanning alerts, and Dependabot security updates. Revoke exposed keys across AWS, GCP, and Azure cloud providers [8].
