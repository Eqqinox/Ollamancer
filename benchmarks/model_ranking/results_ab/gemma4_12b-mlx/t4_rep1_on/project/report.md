## Timeline
The Shai-Hulud supply chain campaign began with a significant resurgence in late 2025, specifically identified as "Shai-Hulud 2.0" [Source: https://unit42.paloaltonetworks.com/npm-supply-chain-attack/]. In early November 2025, researchers observed the first signs of this expanded scope, which affected over 25,000 malicious repositories across approximately 350 unique users [Source: https://unit42.paloaltonetworks.com/npm-supply-chain-attack/]. A major escalation occurred on May 11, 2026, known as "Mini Shai-Hulud," where attackers compromised over 170 npm packages and 2 PyPI packages in a coordinated operation spanning both registries [Source: https://www.microsoft.com/en-us/security/blog/2025/12/09/shai-hulud-2-0-guidance-for-detecting-investigating-and-defending-against-the-supply-chain-attack/]. This campaign represents an aggressive evolution in supply chain threats by targeting the pre-install phase of software dependencies to ensure execution on virtually every build server processing the infected package [Source: https://unit42.paloaltonetworks.com/npm-supply-chain-attack/].

## How it spreads
The attack leverages the `preinstall` phase of software dependencies to execute malicious code before security checks or tests are run [Source: https://unit42.paloaltonetworks.com/npm-supply-chain-attack/, Source: https://www.microsoft.com/en-us/security/blog/2025/12/09/shai-hulud-2-0-guidance-for-detecting-investigating-and-defending-against-the-supply-chain-attack/]. When a developer runs a routine `npm install`, the system resolves a compromised dependency (such as `@tanstack/setup`) and executes an obfuscated script via the Bun runtime [Source: https://www.microsoft.com/en-us/security/blog/2025/12/09/shai-hulud-2-0-guidance-for-detecting-investigating-and-defending-against-the-supply-chain-attack/]. The setup script (`set_bun.js`) identifies if a Bun binary exists; if not found, it installs one to execute bundled malicious scripts like `bun_environment.js` [Source: https://www.microsoft.com/en-us/security/blog/2025/12/09/shai-hulud-2-0-guidance-for-detecting-investigating-and-defending-against-the-supply-chain-attack/]. This script downloads a GitHub Actions Runner archive, configures a new repository, and utilizes tools like TruffleHog to scan the system for stored cloud credentials [Source: https://www.microsoft.com/en-us/security/blog/2025/12/09/shai-hulud-2-0-guidance-for-detecting-investigating-and-defending-against-the-supply-chain-attack/].

The malware functions as a self-replicating worm: it identifies other packages maintained by the compromised developer, injects malicious code into them, and automatically publishes the new versions to the registry [Source: https://unit42.paloaltonetworks.com/npm-supply-chain-attack/]. This automated process allows the malware to spread exponentially without direct actor intervention. If credential theft fails or if the malware cannot authenticate to GitHub/npm tokens, it employs an aggressive fallback mechanism that attempts to destroy the victim's home directory by securely overwriting and deleting every writable file owned by the current user using the `shred` command [Source: https://unit42.paloaltonetworks.com/npm-supply-chain-attack/, Source: https://www.microsoft.com/en-us/security/blog/2025/12/09/shai-hulud-2-0-guidance-for-detecting-investigating-and-defending-against-the-supply-chain-attack/].

## Remediation steps
Organizations should implement commit signature verification to ensure that updates from trusted maintainers are authentic and not impersonated by fake personas like "Linus Torvalds" [Source: https://www.microsoft.com/en-us/security/blog/2025/12/09/shai-hulud-2-0-guidance-for-detecting-investigating-and-defending-against-the-supply-chain-attack/]. Security teams should also monitor for suspicious usage of the `shred` command or unexpected execution of scripts during the package installation phase, as these can indicate data destruction or unauthorized credential exfiltration [Source: https://www.microsoft.com/en-us/security/blog/2025/12/09/shai-hulud-2-0-guidance-for-detecting-investigating-and-defending-against-the-supply-chain-attack/]. Furthermore, enforcing strict access controls on environment variables and ensuring that secrets (such as AWS, GCP, or Azure keys) are never stored in plain text within local configuration files can mitigate the impact of successful credential harvesting [Source: https://unit42.paloaltonetworks.com/npm-supply-chain-attack/]. Additionally, using tools like Microsoft Defender for Containers can help detect suspicious behavior such as command injection to exfiltrate credentials during the build process [Source: https://www.microsoft.com/en-us/security/blog/2025/12/09/shai-hulud-2-0-guidance-for-detecting-investigating-and-defending-against-the-supply-chain-attack/]. Organizations should also ensure that any public repositories created by developers do not contain sensitive information, and they should audit their CI/CD pipelines for unauthorized `preinstall` script executions.
