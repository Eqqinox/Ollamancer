## Timeline

The Shai-Hulud campaign began in September 2025 when researchers identified a self-replicating npm worm that compromised over 40 packages initially, rising to more than 180 affected packages by mid-September [Source: https://arcticwolf.com/resources/blog-uk/wormable-malware-cause-supply-chain-compromise-of-npm-code-packages/] and later exceeding 500 total compromises according to CISA alerts published September 23, 2025 [Source: https://www.cisa.gov/news-events/alerts/2025/09/23/widespread-supply-chain-compromise-impacting-npm-ecosystem].

On November 24, 2025, the community identified Shai-Hulud 2.0 as an escalated variant that had successfully backdoored 796 unique npm packages totaling over 20 million weekly downloads [Source: https://securitylabs.datadoghq.com/articles/shai-hulud-2.0-npm-worm/]. This second wave represented a significant escalation with tens of thousands of GitHub repositories affected across approximately 350 unique users and compromised maintainer accounts from widely used projects including Zapier, PostHog, and Postman [Source: https://unit42.paloaltonetworks.com/npm-supply-chain-attack/].

By December 9, 2025, Microsoft Security reported that the Shai-Hulud 2.0 campaign continued with attackers exfiltrating credentials to public GitHub repositories described as "Sha1-Hulud: The Second Coming" [Source: https://unit42.paloaltonetworks.com/npm-supply-chain-attack/]. In May 2026 (Wave 5), Mini Shai-Hulud resumed activity on May 19, publishing over 630 malicious package versions within approximately 22 minutes and reaching an estimated 16 million weekly downloads by mid-May [Source: https://codeant.ai/blogs/mini-shai-hulud-strikes-again].

## How it spreads

The worm propagates autonomously without requiring a command-and-control server connection. When the malware infects a legitimate npm package, it injects malicious files (setup_bun.js and bun_environment.js for Shai-Hulud 2.0) triggered by adding preinstall scripts [Source: https://unit42.paloaltonetworks.com/npm-supply-chain-attack/]. The attack executes during the pre-install phase of software dependencies before tests or security checks run, eliminating the need for human interaction on build servers processing infected packages [Source: https://securitylabs.datadoghq.com/articles/shai-hulud-2.0-npm-worm/] and bypassing static scanning tools that inspect code at later stages in CI/CD pipelines [Source: https://unit42.paloaltonetworks.com/npm-supply-chain-attack/].

The malware harvests credentials from local filesystem and cloud environments (AWS, Google Cloud Platform, Azure) using credential gathering tools like TruffleHog to scan for sensitive secrets including GitHub Personal Access Tokens and API keys [Source: https://arcticwolf.com/resources/blog-uk/wormable-malware-cause-supply-chain-compromise-of-npm-code-packages/]. Stolen data is exfiltrated through the public GitHub user/repos API to attacker-controlled repositories with specific descriptions identifying them as Shai-Hulud drop points [Source: https://unit42.paloaltonetworks.com/npm-supply-chain-attack/] and uploaded via webhook.site domains monitored by security teams for anomalous outbound connections from build servers processing infected packages [Source: https://www.cisa.gov/news-events/alerts/2025/09/23/widespread-supply-chain-compromise-impacting-npm-ecosystem].

The worm self-replicates by authenticating to npm registry using compromised developer credentials, injecting malicious code into other packages managed by affected developers and publishing backdoored versions that continue propagation through the ecosystem without external coordination [Source: https://www.cisa.gov/news-events/alerts/2025/09/23/widespread-supply-chain-compromise-impacting-npm-ecosystem]. This automated process allows rapid spread across thousands of repositories while evading traditional network defenses monitoring outbound connections.

## Remediation steps

CISA recommends conducting dependency reviews to identify all software leveraging npm, checking package-lock.json or yarn.lock files for affected packages including nested dependencies in build pipelines [Source: https://www.cisa.gov/news-events/alerts/2025/09/23/widespread-supply-chain-compromise-impacting-npm-ecosystem]. Organizations should search artifact repositories and dependency management tools for cached versions of compromised dependencies and pin npm package version references to known safe releases produced prior to September 16, 2025 (the last confirmed malicious update date) [Source: https://www.cisa.gov/news-events/alerts/2025/09/23/widespread-supply-chain-compromise-impacting-npm-ecosystem].

Immediate credential rotation is required after any compromise detection. Teams must mandate phishing-resistant multifactor authentication on developer accounts, especially for critical platforms like GitHub and npm where compromised maintainer credentials enable worm propagation [Source: https://www.cisa.gov/news-events/alerts/2025/09/23/widespread-supply-chain-compromise-impacting-npm-ecosystem]. Network monitoring should detect anomalous outbound connections to webhook.site domains used by the malware as exfiltration endpoints or firewall logs showing suspicious domain communications from build servers processing infected packages [Source: https://www.cisa.gov/news-events/alerts/2025/09/23/widespread-supply-chain-compromise-impacting-npm-ecosystem].

Microsoft Defender provides layered protection covering code, posture management, and runtime detection capabilities that correlate telemetry across data planes including endpoint behavior anomalies and container activity patterns. This defense-in-depth approach helps identify compromised devices flagged by supply chain-driven attacks introducing malicious dependencies evading traditional vulnerability assessment tools used in static scanning processes [Source: https://www.microsoft.com/en-us/security/blog/2025/12/09/shai-hulud-2-0-guidance-for-detecting-investigating-and-defending-against-the-supply-chain-attack/] and provides security coverage from code to runtime behavior detection for CI/CD pipeline compromise scenarios [Source: https://www.microsoft.com/en-us/security/blog/2025/12/09/shai-hulud-2-0-guidance-for-detecting-investigating-and-defending-against-the-supply-chain-attack/] with protection coverage updates noted for Mini Shai-Hulud activity resurgence [Source: https://www.microsoft.com/en-us/security/blog/2025/12/09/shai-hulud-2-0-guidance-for-detecting-investigating-and-defending-against-the-supply-chain-attack/] in May 2026.
