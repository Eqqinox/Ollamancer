
## Timeline

The original Shai-Hulud worm was identified in September 2025, compromising hundreds of npm packages via credential-harvesting malware [Source: https://unit42.paloaltonetworks.com/npm-supply-chain-attack/]. By November 24-25, 2025, "Shai-Hulud 2.0" expanded to over 25,000 malicious repositories across ~350 GitHub users [Source: https://unit42.paloaltonetworks.com/npm-supply-chain-attack/].

The Mini Shai-Hulud resurgence began May 19, 2026: TeamPCP compromised atool's npm account and pushed maliciou versions of 300+ packages including AntV (e.g., @antv/g2) [Source: https://www.chainguard.dev/unchained/mini-shai-hulud-npm-attack-antv-ecosystem-compromise-may-2026]; Microsoft Defender reported protection coverage for this activity by mid-May 2026 [Source: https://www.microsoft.com/en-us/security/blog/2025/12/09/shai-hulud-2-0-guidance-for-detecting-investigating-and-defending-against-the-supply-chain-attack/]. On May 11, TanStack saw 84 malicious artifacts published across 42 packages in six minutes between 19:20-19:26 UTC [Source: https://snyk.io/blog/tanstack-npm-packages-compromised/].

Additional waves followed April-July 2026. The first Mini Shai-Hulud wave started April 29 (also "Shai-Hulud: The Third Coming") with obfuscation to evade detection [Source: https://unit42.paloaltonetworks.com/npm-supply-chain-attack/]; June 1 saw @redhat-cloud-services compromised via Miasma payload bypassing code review entirely [Source: https://www.chainguard.dev/unchained/mini-shai-hulud-npm-attack-antv-ecosystem-compromise-may-2026]. By July 14, attackers hijacked AsyncAPI release pipelines publishing five trojanized npm packages in "miasma-train-p1" attack [Source: https://unit42.paloaltonetworks.com/npm-supply-chain-attack/].

## How it spreads

The Shai-Hulud worm operates as self-replicating malware automating package compromise and redistribution. Initial access is gained through credential-harvesting phishing campaigns spoofing the npm website to steal MFA credentials from developers [Source: https://unit42.paloaltonetworks.com/npm-supply-chain-attack/]. Once inside, the malware deploys post-installation scripts (originally bundle.js in September 2025) or preinstall hooks named setup_bun.js that execute during npm install before security checks can run [Source: https://www.microsoft.com/en-us/security/blog/2025/12/09/shai-hulud-2-0-guidance-for-detecting-investigating-and-defending-against-the-supply-chain-attack/]

The worm's propagation involves three stages: First, it scans for sensitive credentials including .npmrc files and environment variables containing GitHub PATs and cloud service tokens (AWS, GCP, Azure) [Source: https://unit42.paloaltonetworks.com/npm-supply-chain-attack/]. Second, harvested secrets are exfiltrated to attacker-controlled endpoints via public or private repositories with descriptions like "Shai-Hulud Repository" or "Sha1-Hulud: The Second Coming" [Source: https://jfrog.com/blog/shai-hulud-npm-supply-chain-attack-new-compromised-packages-detected/]. Third, using stolen npm credentials, the malware authenticates as the compromised developer and injects malicious code into other packages they maintain, publishing trojanized versions to the public registry without human intervention from threat actors [Source: https://unit42.paloaltonetworks.com/npm-supply-chain-attack/]

The 2.0 variant introduced a fallback sabotage mechanism: if credential theft fails or exfiltration channels are unavailable, it attempts destructive behavior by securely overwriting every writable file in the victim's home directory using shred commands [Source: https://www.microsoft.com/en-us/security/blog/2025/12/09/shai-hulud-2-0-guidance-for-detecting-investigating-and-defending-against-the-supply-chain-attack/]. The attack also leverages Bun runtime (setup_bun.js and bun_environment.js) to execute obfuscated scripts that install GitHub Actions runners for persistence [Source: https://www.microsoft.com/en-us/security/blog/2025/12/09/shai-hulud-2-0-guidance-for-detecting-investigating-and-defending-against-the-supply-chain-attack/]

## Remediation steps

Impacted organizations should immediately rotate all access tokens stored on affected machines across providers including GitHub, NPM, AWS, GCP, Azure, Bitwarden CLI, Aqua Security Trivy scanner credentials (as in March 2026) and any secrets accessible from compromised hosts [Source: https://jfrog.com/blog/shai-hulud-npm-supply-chain-attack-new-compromised-packages-detected/]. Delete malicious files such as .claude/settings.json or repository contents under suspicious accounts. Block known attacker-controlled domains like t.m-kosche.com at the network level to prevent credential exfiltration attempts [Source: https://www.chainguard.dev/unchained/mini-shai-hulud-npm-attack-antv-ecosystem-compromise-may-2026]

Pin npm packages to pre-attack versions and run `npm install --ignore-scripts` followed by manual verification of package integrity before deployment in CI/CD pipelines [Source: https://www.microsoft.com/en-us/security/blog/2025/12/09/shai-hulud-2-0-guidance-for-detecting-investigating-and-defending-against-the-supply-chain-attack/]

Verify commit signatures using Git's GPG key authentication, as attackers have impersonated Linus Torvalds in some commits—a simple check that can confirm who actually created each commit [Source: https://www.microsoft.com/en-us/security/blog/2025/12/09/shai-hulud-2-0-guidance-for-detecting-investigating-and-defending-against-the-supply-chain-attack/]

Organizations should implement SLSA provenance validation to verify packages were built from trusted sources (though this does not guarantee code safety) and deploy build-time security scanning before package publishing. Monitor for suspicious preinstall hook execution, credential harvesting patterns including TruffleHog usage, or the creation of "Shai-Hulud" repositories under victim accounts [Source: https://www.microsoft.com/en-us/security/blog/2025/12/09/shai-hulud-2-0-guidance-for-detecting-investigating-and-defending-against-the-supply-chain-attack/]

Use defense-in-depth approaches correlating telemetry across endpoints, containers, and runtime behavior to detect anomalies early. Microsoft Defender's layered protection covering code scanning through posture management has identified alerts like "Suspicious use of shred command on hidden files detected" for this campaign [Source: https://www.microsoft.com/en-us/security/blog/2025/12/09/shai-hulud-2-0-guidance-for-detecting-investigating-and-defending-against-the-supply-chain-attack/]
