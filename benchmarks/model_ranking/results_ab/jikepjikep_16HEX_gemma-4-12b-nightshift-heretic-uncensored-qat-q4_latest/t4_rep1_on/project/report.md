## Timeline
The Shai-Hulud campaign began as a self-replicating worm in September 2025 [1]. It was initially identified as an evolution in supply chain threats, leveraging automated propagation to achieve significant scale within the npm JavaScript registry [1]. By late 2025, the threat evolved through three discrete waves over nine months, each introducing new capabilities and broader target sets [2]. The campaign reached a historic escalation on April 29, 2026, with the "Mini Shai-Hulud" wave, which simultaneously compromised both the npm and PyPI registries in a single coordinated operation [2].

## How it spreads
The worm operates as a self-replicating entity that systematically hijacks developer accounts and CI/CD pipelines to harvest cloud credentials, GitHub tokens, and API secrets [2]. It uses stolen publisher rights to propagate exponentially into further packages without direct operator intervention [2]. A significant breakthrough in the Shai-Hulud 2.0 campaign was its execution during the pre-install phase of software dependencies [1]. This method completely eliminates the need for human interaction, ensuring that the malware executes on virtually every build server processing the infected package [1]. Furthermore, by targeting this early stage, it effectively bypasses static scanning tools that typically inspect code during later build stages [1]. The campaign is attributed to TeamPCP, a financially motivated group that uses these automated methods to reach tens of thousands of repositories [2].

## Remediation steps
To mitigate the impact of Shai-Hulud, developers should focus on securing high-value cloud credentials and secrets which are primary targets for exfiltration [1]. Because the worm executes during the pre-install phase, it can be mitigated by using tools that specifically check dependencies before they are fully integrated into the build process [1]. Organizations should also monitor their CI/CD pipelines to prevent the malware from crippling entire workflows or locking out internal systems [1]. Finally, since the campaign is attributed to TeamPCP—a financially motivated group—regularly auditing publisher rights and monitoring for "Sha1-Hulud: The Second Coming" descriptions in public repositories can help identify infected packages [2]. Developers should also consider using specific fallback mechanisms to handle cases where a package might attempt to destroy a user's home directory during execution [1].
