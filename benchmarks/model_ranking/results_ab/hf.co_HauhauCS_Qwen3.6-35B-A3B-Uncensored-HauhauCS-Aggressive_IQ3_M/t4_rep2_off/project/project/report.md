# The Shai-Hulud npm Supply-Chain Worm Campaign

## Timeline

The original Shai-Hulud worm first appeared in September 2025, with the earliest malicious publication identified as `rxnt-authentication` version 0.0.3 on September 14, 2025 UTC [1]. Within days it had infected over 477 npm packages, some receiving millions of weekly downloads, making it the first self-replicating malware observed in the npm ecosystem's history [2]. A second generation dubbed "SHA1-Hulud" surfaced in November 2025 with updated wiper functionality and improved credential harvesting [3]. In August 2025 JFrog identified a new variant that compromised over 400 packages across more than 1,700 versions starting from the `keyv` and `cacheable` libraries [4]. A third variant designated "SANDWORM_MODE" introduced adaptive targeting in March 2026, followed by Mini Shai-Hulud — the fourth generation active since late April 2026 — which achieved SLSA Build Level 3 provenance attestation forgery and cross-ecosystem propagation across both npm and PyPI [3]. A major sub-campaign in May 2026, designated CVE-2026-45321, compromised the TanStack ecosystem via chained GitHub Actions exploitation [3].

## How it spreads

The worm begins by compromising a maintainer's credentials — typically through stolen npm tokens, GitHub Personal Access Tokens (PATs), or cloud API keys harvested from CI/CD environments [5]. Once inside an affected package, it injects a malicious `bundle.js` file that executes automatically during `npm install`, triggered via the package.json `postinstall` hook in earlier versions and `preinstall` hooks in later variants [1][4]. The payload scans the environment for secrets using tools like TruffleHog, targeting GitHub tokens, AWS/Azure/GCP credentials, Kubernetes configs, SSH keys, and shell histories [5]. It then exfiltrates collected data to attacker-controlled endpoints or public GitHub repositories named "Shai-Hulud." Using harvested npm tokens with write access, the worm downloads every package owned by the compromised maintainer, injects its payload, bumps the patch version, and publishes it — creating a cascading infection across the registry [5]. In later generations it also commits persistence hooks into `.github/workflows/` files on GitHub repositories, targets up to 100 branches per repo simultaneously, and extracts OIDC tokens directly from CI runner process memory [3][4]. Mini Shai-Hulud additionally propagates across both npm and PyPI ecosystems and forges SLSA Build Level 3 provenance attestations to pass cryptographic verification [3].

## Remediation steps

Organizations should immediately pin all npm package dependencies to known-safe versions released before September 16, 2025 [5]. All developer credentials — particularly GitHub PATs, npm tokens, and cloud API keys — must be rotated without delay. Phishing-resistant multifactor authentication (MFA) should be mandated on all developer accounts for critical platforms including GitHub and npm [5]. Teams should audit and remove unnecessary GitHub Apps and OAuth applications, review repository webhooks and secrets, and enable branch protection rules along with GitHub Secret Scanning alerts [5]. Network monitoring should block outbound connections to `webhook.site` domains commonly used by the worm's command-and-control infrastructure. For Mini Shai-Hulud specifically, organizations using npm 12 or newer benefit from its default behavior of not running preinstall hooks unless explicitly enabled [4]. Finally, teams should check for `.github/workflows/shai-hulud-workflow.yml` files and branches named `shai-hulud`, `-migration`, or `dependabot/github_actions/format/setup-formatter` in all repositories that used compromised packages [1][3].
