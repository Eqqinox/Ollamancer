## Timeline

The Shai-Hulud campaign began in September 2025 as a self-replicating npm worm compromising hundreds of software packages [Source: https://unit42.paloaltonetworks.com/npm-supply-chain-attack/] [Source: https://securitylabs.datadoghq.com/articles/shai-hulud-2.0-npm-worm/]. In November 2025, "Shai-Hulud 2.0" expanded to affect tens of thousands of GitHub repositories across approximately 350 unique users [1][Source: https://unit42.paloaltonetworks.com/npm-supply-chain-attack/] [Source: https://securitylabs.datadoghq.com/articles/shai-hulud-2.0-npm-worm/], with execution during pre-install phases dramatically widening impact and introducing fallback mechanisms that could destroy victim home directories if credential theft failed [1][3].

By November 24, 2026 at approximately 6 p.m. UTC, the last affected package was published as npm took measures to prevent further backdooring of packages [Source: https://securitylabs.datadoghq.com/articles/shai-hulud-2.0-npm-worm/] [3]. In May 2026, "Mini Shai-Hulud" emerged from TeamPCP-linked activity affecting more than 170 npm packages and two PyPI packages [Source: https://www.hexnode.com/blogs/poisoned-at-the-root-shai-hulud-worm-copycats-2026-and-npm-developer-endpoint-risk/] [4]. Researchers reported that around early-mid-2025 the threat actor appeared to publish source code with deployment-style instructions on GitHub, enabling copycat attacks including typo-squatted variants like chalk-tempalte published alongside other malicious packages from compromised accounts [3][Source: https://www.hexnode.com/blogs/poisoned-at-the-root-shai-hulud-worm-copycats-2026-and-npm-developer-endpoint-risk/].

## How it spreads

Shai-Hulud exploits npm's lifecycle script mechanism during package installation. The malware injects two files—setup_bun.js and bun_environment.js—and triggers them by adding preinstall or post-install scripts that run automatically when developers install poisoned packages, achieving complete automation without requiring human interaction while bypassing static scanning tools focused on later build stages [1][Source: https://unit42.paloaltonetworks.com/npm-supply-chain-attack/] [3].

The worm operates in multiple phases: first installing Bun JavaScript runtime to evade Node.js monitoring and execute obfuscated payloads; then harvesting credentials from .npmrc files, environment variables, cloud configuration (AWS GCP Azure), secrets managers like AWS Secrets Manager and Google Cloud Secret Manager [2][Source: https://securitylabs.datadoghq.com/articles/shai-hulud-2.0-npm-worm/] [3]. Harvested data is exfiltrated via public GitHub repositories with descriptions set as "Sha1-Hulud: The Second Coming," or through automated searches for existing compromised credentials from other victims if the attacker lacks direct access to victim accounts [Source: https://securitylabs.datadoghq.com/articles/shai-hulud-2.0-npm-worm/].

Once credentials are stolen, malware authenticates to npm using those tokens and identifies packages maintained by the same developer account. It then injects malicious code into up to 100 of these discovered packages before publishing them as new versions—enabling exponential self-replication without actor intervention while setting up GitHub-based workers for remote execution on compromised machines [Source: https://unit42.paloaltonetworks.com/npm-supply-chain-attack/] [3].

## Remediation steps

Security teams should immediately remove any malicious packages from project lockfiles or dependency trees. Affected developers must inspect all installed npm versions against known lists of backdoored packages, particularly those with preinstall scripts that may have been modified after initial publication [4][Source: https://www.hexnode.com/blogs/poisoned-at-the-root-shai-hulud-worm-copycats-2026-and-npm-developer-endpoint-risk/]. Organizations need to isolate compromised developer machines and CI/CD runners by disconnecting them while preserving logs for forensic analysis before reconnection.

Credential rotation is critical: all exposed GitHub tokens, cloud API keys (AWS GCP Azure), npm access tokens, and other secrets must be revoked immediately with new credentials generated after the incident [1][Source: https://unit42.paloaltonetworks.com/npm-supply-chain-attack/]. Developers should audit public repositories to check if any contain "Sha1-Hulud" related files or descriptions indicating compromise. Hardening includes disabling automatic installation of devDependencies where possible, implementing stricter package verification through provenance tools like Snyk and Renovate alerts for suspicious packages [3][Source: https://www.hexnode.com/blogs/poisoned-at-the-root-shai-hulud-worm-copycats-2026-and-npm-developer-endpoint-risk/].

Additional measures include removing persistence artifacts from home directories; scanning all writable files owned by current users under their home folders using security scanners or custom scripts checking file timestamps against known malware indicators. Teams should enable identity-aware access controls, implement threat response automation via monitoring tools like TruffleHog and cloud instance metadata service alerts [3][Source: https://www.hexnode.com/blogs/poisoned-at-the-root-shai-hulud-worm-copycats-2026-and-npm-developer-endpoint-risk/].
