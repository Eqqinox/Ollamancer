## Timeline
Shai‑Hulud is the codename for a self‑replicating npm supply‑chain worm that first surfaced in late 2025. The initial public alert was issued by CISA on September 23, 2025 after an investigation revealed more than 500 packages had been compromised [Source: https://www.cisa.gov/news-events/alerts/2025/09/23/widespread-supply-chain-compromise-impacting-npm-ecosystem]. Unit 42 followed with a detailed update on November 25, 2025 describing the expanded Shai‑Hulud 2.0 campaign that had already infected tens of thousands of GitHub repositories and over 25,000 npm releases by early December 2025 [Source: https://unit42.paloaltonetworks.com/npm-supply-chain-attack/]. Microsoft’s security blog issued guidance on December 9, 2025 and later noted a resurgence in May 2026 with the Mini Shai‑Hulud variant, confirming ongoing activity into mid‑2026 [Source: https://www.microsoft.com/en-us/security/blog/2025/12/09/shai-hulud-2-0-guidance-for-detecting-investigating-and-defending-against-the-supply-chain-attack/].

## How it spreads
The worm operates by inserting malicious code into npm packages during the pre‑install phase. When an infected package is installed, the payload executes before any tests or static analysis can run, allowing it to harvest credentials from the build environment and user accounts [Source: https://unit42.paloaltonetworks.com/npm-supply-chain-attack/][Source: https://www.microsoft.com/en-us/security/blog/2025/12/09/shai-hulud-2-0-guidance-for-detecting-investigating-and-defending-against-the-supply-chain-attack/]. After collecting GitHub Personal Access Tokens (PATs) and cloud API keys for AWS, GCP, and Azure, the malware exfiltrates them to an actor‑controlled endpoint and uploads them to a public repository named Shai‑Hulud via the GitHub /user/repos API [Source: https://www.cisa.gov/news-events/alerts/2025/09/23/widespread-supply-chain-compromise-impacting-npm-ecosystem]. With those credentials it authenticates as the compromised maintainer on npmjs.com, injects malicious code into other popular packages, publishes new infected versions, and repeats the cycle—effectively self‑replicating across the entire JavaScript ecosystem [Source: https://www.cisa.gov/news-events/alerts/2025/09/23/widespread-supply-chain-compromise-impacting-npm-ecosystem][Source: https://unit42.paloaltonetworks.com/npm-supply-chain-attack/]. The worm’s design allows it to bypass traditional static scanning tools that inspect code only after installation, making detection difficult until a package is actually used in a build.

## Remediation steps
1. **Audit dependencies** – Scan all projects for affected lock files (package‑lock.json or yarn.lock) and identify any package that has been updated after September 16, 2025; pin to a known safe release before that date [Source: https://www.cisa.gov/news-events/alerts/2025/09/23/widespread-supply-chain-compromise-impacting-npm-ecosystem].
2. **Rotate credentials** – Immediately revoke all developer GitHub PATs, npm tokens, and cloud API keys, then issue new ones with the least privilege required [Source: https://www.cisa.gov/news-events/alerts/2025/09/23/widespread-supply-chain-compromise-impacting-npm-ecosystem][Source: https://unit42.paloaltonetworks.com/npm-supply-chain-attack/].
3. **Enforce MFA** – Require phishing‑resistant multi‑factor authentication on all accounts that can publish to npm or access cloud services [Source: https://www.cisa.gov/news-events/alerts/2025/09/23/widespread-supply-chain-compromise-impacting-npm-ecosystem].
4. **Monitor outbound traffic** – Block connections to known malicious domains (e.g., webhook.site) and watch for unusual API calls from CI/CD pipelines [Source: https://www.cisa.gov/news-events/alerts/2025/09/23/widespread-supply-chain-compromise-impacting-npm-ecosystem].
5. **Apply layered defense** – Deploy Microsoft Defender or equivalent runtime protection that correlates telemetry across code, posture management, and container behavior; this helps detect pre‑install execution attempts and anomalous credential exfiltration [Source: https://www.microsoft.com/en-us/security/blog/2025/12/09/shai-hulud-2-0-guidance-for-detecting-investigating-and-defending-against-the-supply-chain-attack/].
6. **Rebuild affected packages** – Re‑publish clean versions of any compromised libraries from trusted source control, ensuring no malicious payload remains.
7. **Educate developers** – Provide training on supply‑chain hygiene, emphasizing the risks of installing untrusted or newly published packages and encouraging code reviews before publishing.
